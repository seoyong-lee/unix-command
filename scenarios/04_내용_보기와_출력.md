# 실습 4단계 — 파일 내용 보기와 텍스트 출력

## 학습 목표

`cat`으로 파일 내용을 확인하고 `echo`와 `>` · `>>`로 파일에 글을 쓰거나 덧붙일 수 있습니다.

---

## 배경 시나리오

> 서버 로그를 확인하고 환경 변수 파일을 새로 만들어야 합니다.
> 에디터를 열지 않고 터미널만으로 파일 내용을 다뤄 봅시다.

---

## 명령어 요약

| 명령어 | 설명 | 기본 형식 |
| --- | --- | --- |
| `cat` | 파일 내용 출력 · 여러 파일 이어 붙이기 | `cat [옵션] 파일...` |
| `echo` | 뒤에 적은 글자 출력 | `echo "텍스트"` |

| 기호 · 옵션 | 설명 |
| --- | --- |
| `cat -n` | 줄 번호 표시 (number) |
| `>` | 출력을 파일에 저장 (파일이 있으면 **기존 내용을 지우고** 새로 씀) |
| `>>` | 출력을 파일 **끝에 추가** |

> 💡 `>`와 `>>`의 차이가 이 단계의 핵심입니다.

---

## 실습 문제

### 준비

```bash
cd ~/Desktop/unix-command/practice
```

---

### 문제 1 — 파일 내용 보기

```bash
cat notes.txt
cat website/index.html
```

---

### 문제 2 — 줄 번호와 함께 보기

```bash
cat -n configs/server.conf
```

> 🔍 에러 메시지가 "몇 번째 줄"을 가리킬 때 줄 번호가 있으면 찾기 쉽습니다.

---

### 문제 3 — 두 파일 이어서 보기

`cat`의 원래 뜻(concatenate)은 여러 파일을 이어 붙이는 것입니다.

```bash
cat logs/access.log logs/error.log
```

---

### 문제 4 — echo로 글자 출력하기

```bash
echo "숲속 책방에 오신 것을 환영합니다"
```

---

### 문제 5 — 파일 만들기 (>)

```bash
echo "BOOKSTORE_ENV=development" > configs/.env
ls configs
ls -a configs
cat configs/.env
```

> 🔍 `.env`는 점으로 시작하는 숨김 파일이라 `ls -a`에서만 보입니다.

---

### 문제 6 — 파일 끝에 덧붙이기 (>>)

```bash
echo "PORT=8080" >> configs/.env
cat configs/.env
```

---

### 문제 7 — 덮어쓰기 실수 재현하기 (>)

```bash
echo "DEBUG=true" > configs/.env
cat configs/.env
```

> ⚠️ 앞의 두 줄이 사라지고 한 줄만 남았습니다. 기록을 **쌓을 때는 반드시 `>>`** 를 씁니다.

---

### 문제 8 — 로그 한 줄 남기기

```bash
echo "[2026-10-08 11:20:00] INFO  실습 4단계 완료" >> logs/access.log
cat -n logs/access.log
```

## 확인 질문

1. `echo "hi" > a.txt`와 `echo "hi" >> a.txt`는 무엇이 다를까요?
2. `cat -n`의 `-n`은 무엇을 해 줄까요?
3. `ls`로는 `.env` 파일이 보이지 않는 이유는 무엇일까요?

<details>
<summary>답 보기</summary>

1. `>`는 파일을 새로 쓰고(기존 내용 삭제) `>>`는 파일 끝에 이어 붙입니다.
2. 줄 번호를 붙여서 출력합니다.
3. 이름이 `.`으로 시작하는 숨김 파일이라서입니다. `ls -a`로 봅니다.
</details>
