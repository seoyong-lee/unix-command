# 실습 2단계 — 파일과 폴더 만들고 지우기

## 학습 목표

`mkdir`, `touch`, `rm`으로 파일과 폴더를 만들고 필요 없는 것을 지울 수 있습니다.

---

## 배경 시나리오

> 책방에 '가을 독서 이벤트' 페이지를 새로 만들기로 했습니다.
> 기능별로 폴더를 나누고 필요한 파일을 미리 만든 뒤 잘못 만든 것은 깔끔하게 정리해 봅시다.

---

## 명령어 요약

| 명령어 | 설명 | 기본 형식 |
| --- | --- | --- |
| `mkdir` | 폴더 만들기 | `mkdir [옵션] 폴더명` |
| `touch` | 빈 파일 만들기 (있는 파일이면 수정 시각만 바뀜) | `touch 파일명` |
| `rm` | 파일 · 폴더 삭제 | `rm [옵션] 대상` |

| 옵션 | 설명 |
| --- | --- |
| `mkdir -p` | 중간 폴더까지 한 번에 만들기 (parents) |
| `rm -r` | 폴더와 안의 내용까지 삭제 (recursive) |
| `rm -i` | 지우기 전에 하나씩 확인 (interactive) |
| `rm -f` | 확인 · 오류 없이 강제로 삭제 (force) |

> ⚠️ **주의:** `rm`으로 지운 파일은 휴지통에 들어가지 않고 **바로 사라집니다.** 되돌릴 방법이 없습니다.
> `rm -rf` 전에는 `pwd`와 `ls`로 위치와 대상을 꼭 확인합니다.

---

## 실습 문제

### 준비

```bash
cd ~/Desktop/unix-command/practice
```

---

### 문제 1 — 새 기능 폴더 만들기

이벤트 페이지와 서평 페이지를 위한 폴더를 한 번에 만듭니다.

```bash
mkdir event review
ls
```

---

### 문제 2 — 중첩 폴더 한 번에 만들기

`api/v1/books` 폴더를 만들어 봅니다.

```bash
mkdir api/v1/books       # 오류가 납니다. 이유를 읽어 보세요.
mkdir -p api/v1/books    # 중간 폴더까지 한 번에 만들기
ls -R api
```

> 💡 `ls -R`은 하위 폴더 안까지 모두 보여 줍니다.

---

### 문제 3 — 파일 만들기

`event` 폴더 안에 HTML · CSS · JS 파일을 한 줄로 만듭니다.

```bash
touch event/event.html event/event.css event/event.js
ls -l event
```

> 🔍 크기가 `0`인 빈 파일이 만들어졌습니다.

---

### 문제 4 — 이미 있는 파일에 touch 하기

```bash
ls -l notes.txt
touch notes.txt
ls -l notes.txt
```

> 🔍 내용과 크기는 그대로이고 **수정 시각**만 지금으로 바뀝니다. 시각이 같다면 1분쯤 뒤에 다시 해 보세요.

---

### 문제 5 — 오타 파일 지우기

```bash
touch event/evnet.html   # 오타로 만든 파일 (실수 재현)
ls event
rm event/evnet.html
ls event
```

---

### 문제 6 — 확인하며 지우기 (-i)

```bash
touch temp.txt
rm -i temp.txt
# remove ... ? 라고 물으면 y를 입력하고 Enter
```

---

### 문제 7 — 폴더 지우기

```bash
rm review            # 오류: 폴더는 -r이 있어야 지워집니다
rm -r review
rm -r api
ls
```

## 확인 질문

1. 이미 있는 파일에 `touch`를 하면 무엇이 바뀔까요?
2. `mkdir`과 `mkdir -p`의 차이는 무엇일까요?
3. `rm -rf`를 조심해야 하는 이유는 무엇일까요?

<details>
<summary>답 보기</summary>

1. 내용은 그대로이고 수정 시각만 지금 시각으로 바뀝니다.
2. `mkdir`은 부모 폴더가 없으면 오류가 나고 `mkdir -p`는 중간 폴더까지 모두 만듭니다.
3. 휴지통 없이 바로 지우고 `-f` 때문에 확인도 묻지 않아서 경로를 잘못 적으면 되돌릴 수 없습니다.
</details>
