# 실습 5단계 — 파일 권한과 소유자

## 학습 목표

`ls -l`의 권한 문자열을 읽고 `chmod`로 권한을 바꿀 수 있습니다. `chown`이 무엇을 하는지 설명할 수 있습니다.

---

## 배경 시나리오

> 배포 스크립트를 실행했더니 `Permission denied`가 나옵니다.
> 또 보안 규칙상 서버 설정 파일은 다른 사람이 읽지 못하게 막아야 합니다.
> 파일 권한을 읽고 알맞게 바꿔 봅시다.

---

## 핵심 개념 — 권한 읽는 법

`ls -l` 결과의 첫 칸 예시: `-rwxr-xr--`

| 위치 | 예시 | 의미 |
| --- | --- | --- |
| 1번째 | `-` | 파일 타입 (`-` 일반 파일 · `d` 디렉터리 · `l` 링크) |
| 2~4번째 | `rwx` | **소유자(u)** 권한 |
| 5~7번째 | `r-x` | **그룹(g)** 권한 |
| 8~10번째 | `r--` | **기타 사용자(o)** 권한 |

| 기호 | 숫자 | 파일에서 | 디렉터리에서 |
| --- | --- | --- | --- |
| `r` | 4 | 읽기 | 목록 보기 |
| `w` | 2 | 수정 | 안에 파일 만들기 · 지우기 |
| `x` | 1 | 실행 | 들어가기(`cd`) |
| `-` | 0 | 권한 없음 | 권한 없음 |

세 글자의 숫자를 더합니다. `rwx` = 7, `rw-` = 6, `r-x` = 5, `r--` = 4

| 숫자 | 문자 | 용도 |
| --- | --- | --- |
| `755` | `rwxr-xr-x` | 실행 파일 · 폴더 |
| `644` | `rw-r--r--` | 일반 파일 (HTML · CSS · JS) |
| `600` | `rw-------` | 비밀 파일 (설정 · 키) |
| `777` | `rwxrwxrwx` | 누구나 수정 · 실행 — **쓰지 않습니다** |

---

## 명령어 요약

| 명령어 | 설명 | 기본 형식 |
| --- | --- | --- |
| `chmod` | 권한 바꾸기 (change mode) | `chmod u+x 파일` · `chmod 644 파일` · `chmod -R 755 폴더` |
| `chown` | 소유자 바꾸기 (change owner, 관리자 권한 필요) | `sudo chown 사용자:그룹 파일` |

## 실습 문제

### 준비

```bash
cd ~/Desktop/unix-command/practice
ls -l configs
```

---

### 문제 1 — 권한 읽어 보기

```bash
ls -l configs/deploy.sh
```

> 🔍 `deploy.sh`에 실행(`x`) 권한이 있나요? 소유자 · 그룹 · 기타 순서로 읽어 보세요.

---

### 문제 2 — 실행 권한 없이 실행해 보기

```bash
./configs/deploy.sh
```

> 🔍 `Permission denied`가 나옵니다. `./`는 "지금 위치 기준으로 이 파일을 실행하라"는 뜻입니다.

---

### 문제 3 — 실행 권한 주기 (기호 방식)

```bash
chmod u+x configs/deploy.sh
ls -l configs/deploy.sh
./configs/deploy.sh
```

> 💡 `u` 소유자 · `g` 그룹 · `o` 기타 · `a` 모두 / `+` 추가 · `-` 제거 / `r` `w` `x`

---

### 문제 4 — 비밀 설정 파일 잠그기 (숫자 방식)

```bash
chmod 600 configs/server.conf
ls -l configs/server.conf
```

> 🔐 비밀번호나 키가 들어 있는 파일은 `600`(나만 읽고 쓰기)으로 둡니다.

---

### 문제 5 — 잘못 준 권한 바로잡기

누군가 "권한 오류가 나서" `777`을 줘 버린 상황을 재현하고 바로잡습니다.

```bash
chmod 777 website/index.html        # 잘못된 설정 (누구나 수정 · 실행 가능)
ls -l website/index.html
chmod 644 website/index.html        # 웹 파일은 644
ls -l website/index.html
```

> 🔍 `-rwxrwxrwx`가 `-rw-r--r--`로 돌아왔습니다. 웹 서버에 올리는 HTML · CSS · JS 파일은 `644`가 기본입니다.

---

### 문제 6 — 폴더 권한 바꾸기

```bash
chmod 700 logs
ls -l
```

> 🔍 `logs` 줄의 권한이 `drwx------`로 바뀌었습니다. 폴더에서 `x`는 들어갈 수 있는 권한입니다.
> 💡 폴더와 안의 파일까지 한꺼번에 바꾸려면 `chmod -R`을 씁니다. `R`은 **대문자**입니다.

---

### 문제 7 — 소유자 확인하기 (chown은 설명만)

```bash
whoami
ls -l configs/server.conf
```

> 💡 세 번째 칸이 소유자, 네 번째 칸이 그룹입니다.
> 소유자를 바꾸는 `sudo chown 사용자:그룹 파일`은 관리자 비밀번호가 필요해서 이번 실습에서는 입력하지 않습니다. 서버에서 주로 씁니다.

---

### 문제 8 — 새 스크립트 만들고 실행하기

4단계의 `echo`와 이번 단계의 `chmod`를 함께 씁니다.

```bash
echo '#!/bin/bash' > configs/open.sh
echo 'echo "숲속 책방 문을 엽니다. http://localhost:8080"' >> configs/open.sh
cat configs/open.sh
ls -l configs/open.sh
chmod 755 configs/open.sh
./configs/open.sh
```

---

## 확인 질문

1. `-rw-r--r--`를 숫자로 바꾸면 무엇일까요?
2. `./deploy.sh`를 실행했더니 `Permission denied`가 나왔습니다. 어떻게 해결할까요?
3. `chmod 777`을 쓰지 않는 이유는 무엇일까요?

<details>
<summary>답 보기</summary>

1. `644`입니다.
2. `chmod u+x deploy.sh`(또는 `chmod +x`, `chmod 755`)로 실행 권한을 줍니다.
3. 누구나 읽고 고치고 실행할 수 있게 되어 보안상 위험합니다. 필요한 권한만 줍니다.
</details>

---

> **Windows Git Bash 사용자**: Windows 파일 시스템에서는 `chmod` 결과가 `ls -l`에 그대로 보이지 않을 수 있습니다.
> `./configs/deploy.sh`가 실행되지 않으면 `bash configs/deploy.sh`로 실행해 결과를 확인하세요.
